The Development Loop

The day-to-day loop: start the dev server, edit, create components, run the fast checks, document, build and serve.

Day-to-day Slice work is a short loop: start the dev server, change a component, see it reload, and run the fast checks before you build. The same loop applies to a new project and to one that has been running for months.

The loop at a glance

  1. Start the dev server with slice dev.
  2. Create or edit the component and let the dev server reload it.
  3. Assign a prop, call a method, or use update() — do not rebuild for a prop change.
  4. Run slice doctor, slice lint and slice typecheck.
  5. Run slice build, then slice start to verify the production output.

1. Start: slice dev

slice dev serves the app from src/ with hot reload. Changes to .js, .html and .css reload the page; changes to sliceConfig.json may need a restart. Before watching, it regenerates the project documentation (AGENTS inventory, declarations and docs/events/).

  • Port: server.port in sliceConfig.json, or slice dev -p 4000. The default is 3000; if it is taken, the CLI falls back to the next free port.
  • Debug panels: alt+shift+e (events) and alt+shift+c (context) when events.ui.enabled / context.ui.enabled are on.
  • Inspect props: right-click a component when debugger.enabled is on.

If you use package.json scripts, pnpm run dev / npm run dev are the same command pinned to the project's local CLI.

3. Check before you build

  • slice doctor is the fast static check: config, component files, routes, prop definitions, imports, SEO and common lifecycle mistakes. It exits 0 with warnings and 1 on failures.
  • slice lint runs ESLint with the shared Slice config.
  • slice typecheck runs the project's own TypeScript against the generated declarations.

Doctor does not compile or bundle. It can prove the project is structurally sound; it cannot prove that esbuild resolves the whole graph. That is what slice build is for.

4. Documentation is part of the loop

slice dev regenerates before it starts watching, and slice build runs the drift check for a scaffolded project. Update the Markdown and the component README.md when behavior changes; see Documentation & AGENTS.md.

5. Build and serve

slice build analyzes what the routes use, bundles and minifies into dist/, copies src/public/ to dist/public/, checks the generated docs, and never writes into src/. slice start serves dist/; if the build is missing, it runs slice build first.

For a static host, slice export packages the build for dist-static/ (experimental); see CLI Commands.
