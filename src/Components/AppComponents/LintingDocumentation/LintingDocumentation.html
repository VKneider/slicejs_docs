Linting

Slice ships an [ESLint](https://eslint.org) flat config with the CLI. One import gives a Slice project the browser environment, the slice/Slice globals, a sane rule set, and ignores for generated output — without every project inventing its own config.

Lint is for editor-time mistakes. It does not decide whether a project ships: that is [slice build](/Documentation/CLI#build) and [slice doctor](/Documentation/CLI#doctor).

Set it up

New to the project? One command installs ESLint, writes eslint.config.js (only if you do not have one) and adds lint / lint:fix scripts:

slice setup lint --dry-run prints the plan without touching anything. It never overwrites a config or a script you already have, so running it twice is safe.

slice init does not install ESLint: the linter is a choice, and choosing it later is one command.

Run it

slice lint runs the ESLint installed in your project — the CLI does not bundle it. If ESLint is missing, the command says so and tells you how to install it. Any editor with ESLint support picks up eslint.config.js on its own; no extra configuration.

What the shared config provides

The default export is the app preset:

  • @eslint/js recommended, as errors.
  • Browser globals plus slice and Slice for src/.
  • Node globals for api/, scripts/ and *.config.js — the server side is Node, not browser.
  • Node + browser globals (and Playwright's page/browser) for *.spec.js, tests/** and

playwright/**.

  • A small set of rules as warnings, so a long-green project does not turn red overnight

(no-unused-vars with the _ convention, no-duplicate-imports, no-template-curly-in-string, …).

  • Ignores for dist/, node_modules/, src/libs/, *.generated.js, src/Components/components.js

and the agent folders (.agents/, .claude/, .opencode/).

What lint does not do

Lint parses JavaScript. It has no type information: the shared config does not enable typescript-eslint, there is no tsconfig.json in a Slice app, and the .d.ts generated by slice types generate is read by your editor and by tsc, not by ESLint.

What slice lint does do is keep that .d.ts honest: before running ESLint it regenerates the declarations (and the event manifest) when the project uses them — a slice:types script or an existing src/slice-build.generated.d.ts. If the props changed, the file is updated and the command says so, so a commit carries the current types. --no-types skips the phase.

That keeps the declarations current, but it is still not a type *check*: ESLint never compares your code against them. A compiler does that, and it is one command away.

Remember that the type generator reads the AST: type, allowedValues, schema and items must be written literally. A constant is invisible to it and the prop falls back to any (see [Static Props](/Documentation/Static-Props)). slice types generate warns when it finds one, and so do slice build and slice doctor.

Type checking

slice typecheck runs your own TypeScript over the project with the jsconfig.json that slice types generate maintains (allowJs + checkJs, modern target and libs, specs excluded).

Or let the setup do both:

It installs TypeScript, writes the ESLint config as usual, and adds a typecheck script. If the project already has a jsconfig.json/tsconfig.json, slice typecheck uses it (-p overrides).

What it catches: a slice.build('X', { … }) whose props do not match X's static props, an event payload with the wrong shape, a property that does not exist. The generated declarations are what make the framework API typed; the rest of your code is checked as JavaScript, with strict off by default so a JS app does not need annotations to pass.

It is slower than lint and needs a compiler installed, so it is a separate command: lint stays fast for the editor, typecheck runs in CI.

In CI

slice doctor and slice lint exit 1 on failures; doctor rows marked as warnings (unscoped CSS, a destroy() the framework never calls, an unregistered name in slice.build) exit 0. slice build blocks on anything that would ship a broken bundle — see [CLI](/Documentation/CLI#validation-on-build) for the exact split between lint, doctor and build.
