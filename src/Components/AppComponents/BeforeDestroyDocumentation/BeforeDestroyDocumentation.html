beforeDestroy()

Cleanup hooks for timers, listeners, requests and Services that outlive the component.

Overview

beforeDestroy() runs right before a component is destroyed by the controller. Use it for cleanup: timers, listeners, subscriptions, pending async work, and Services you built by hand.

The controller does not await this method, so keep it synchronous or fire-and-forget.

A method named destroy(), dispose() or teardown() looks like cleanup but never runs — the controller only calls beforeDestroy(). slice doctor reports that, and it reports a window/document listener added without a matching removeEventListener in the same file unless it uses { once: true } or { signal }.

What is already cleaned up?

The split matters: the parent destroy cascade reaches Visual children, but a Service has no DOM, so nothing discovers it.

API

Ideal use cases

  • Clear intervals and timeouts.
  • Abort pending fetch requests.
  • Remove global event listeners.
  • Dispose third-party instances (charts, maps, etc.).
  • Destroy child Services you built with slice.build.

Example

Keep beforeDestroy() idempotent: it can be called more than once in a teardown sequence, and every cleanup inside it must tolerate that.
