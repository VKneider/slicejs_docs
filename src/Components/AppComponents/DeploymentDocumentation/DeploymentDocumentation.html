Deployment

Overview

A Slice app can be served in two ways:

Both start from the same production build. slice build compiles the app into dist/; slice export reads that build and writes a flattened, host-ready copy to dist-static/.

Use Express when you need server middleware, /api/* routes, server-side headers, or a long-running Node process. Use static when the app is entirely client-side and you want Cloudflare Pages, Netlify, Vercel, nginx, GitHub Pages or S3 + CloudFront.

The export is root-only. Serve it at the root of a domain (https://example.com/) or a subdomain (https://app.example.com/). Subpath hosting (https://user.github.io/repo/) is not supported.

Build once, deploy twice

dist/ is the Express/serverless layout:

slice export flattens dist/public/* to the root, creates index.html and 404.html, prerenders routes when SEO is configured, copies the env pair, and writes host rules. dist-static/ is the folder you upload.

Why not a single dist? dist/ must keep the shape Express serves (App/ at /App, public/ at /, explicit root files). A static host needs a different shape (public/* at /, root index.html, 404.html). Keeping the artifacts separate makes the upload boundary explicit and avoids breaking slice start. See [Static export](#static-export) below.

New projects get dist-static/ in .gitignore. If your project predates the export command, add it yourself.

Express hosting

slice start:

  • requires src/ and api/ (the server entrypoint lives in api/index.js),
  • serves dist/ in production,
  • runs slice build automatically if dist/ or

dist/bundles/bundle.config.json is missing,

  • resolves the port as --port → sliceConfig.server.port → 3000; if that

port is busy it tries port + 1,

  • keeps slice dev for development (src/, HMR).

Production exposes only:

  • dist/public/* at / (Themes, Styles, images, PWA),
  • /App/*,
  • /routes.js and /sliceConfig.json,
  • /bundles/* and the legacy /dist/bundles/* mirror,
  • /Slice/Slice.js,
  • /slice-env.json and /slice-env.generated.js,
  • /service-worker.js and /manifest.json,
  • translator dictionaries under their configured folder.

It does not expose /Components, the rest of the /dist tree, .map, .d.ts, .env, package.json or node_modules. A real 404 requires SEO; see [SEO and Share Cards](/Documentation/Architecture/SEO). Without SEO the fallback returns the shell with 200 (a soft 404).

Output

Components/ is pruned by default: every component used at runtime is in a bundle, and Express production also 404s /Components. --keep-components is a debugging escape and the CLI warns that component source becomes fetchable.

The export is an allowlist. It never publishes utils/, AppConfig.js, slice-events.generated.js, generated .d.ts, .map, .map.br, .map.gz, .env*, package.json, lockfiles, node_modules or .git. If a file is not in the allowlist, it is not uploaded.

Options

404 and redirects

With SEO:

  • every literal route is prerendered to <route>/index.html,
  • 404.html is a real not-found page with noindex,
  • there is no catch-all, so unknown routes get a real 404,
  • locale redirects are written as host rules (_redirects, vercel.json,

nginx location) or as portable HTML meta refresh pages for hosts without server rules (GitHub Pages, S3, --host none).

--spa restores the client-router fallback, but the mechanics depend on the host:

Use --spa only when the router must handle deep links that were not prerendered.

Without SEO the shell is the only page and the SPA fallback is on by default.

Dynamic routes

${param} routes cannot be enumerated. Two options:

  1. List concrete values in seo.json:

``json { "routes": { "/projects/${slug}": { "sitemap": { "paths": ["alpha", "beta"] } } } } ``

  1. Pass --spa and let the client router resolve the route.

Backend routes (/api)

A static export is just files: **there is no Express and no /api/***. Do not point /api at the SPA fallback; it returns HTML, not JSON.

If the app needs backend routes, use the Express server that ships with Slice:

Deploy it on a Node host (Render, Fly, Railway, a VPS, Docker, or a serverless adapter). A serverless adapter that imports the app instead of running it should mount sliceFallback() and sliceErrorHandler() by hand, as Conclave does.

The static and Express modes are not mutually exclusive: you can keep the frontend static and call a separate API origin with SLICE_PUBLIC_API_URL.

Service worker

service-worker.js is app-owned: Slice serves it and copies it into the build, but it does not generate the caching policy. For a static export:

  • every PRECACHE path must exist in dist-static/;
  • do not precache /Components/... (the exporter prunes it by default);
  • bump the cache name on every deploy, or use --hash-filenames;
  • if you want a new worker to take over immediately, call skipWaiting() in

install and clients.claim() in activate (the PWA guide shows the pattern);

  • do not cache /api/* responses in a static export, because there is no API.

See [Make Your App a PWA](/Documentation/Configuration/PWA) for the full worker example.

Preview locally

This respects 404.html and the prerendered route files. Do not use npx serve -s to validate the 404: the -s flag forces an SPA fallback and hides the real 404.html. Use npx serve -s only when you intentionally want to test --spa behavior.

slice start serves dist/, not dist-static/; there is no built-in static preview command.

Host matrix

Cloudflare Pages / Netlify

Upload dist-static/. The exporter writes _redirects and _headers:

  • locale redirects,
  • security headers,
  • Cache-Control: no-store for /bundles/* and the env pair.

Cloudflare Pages has no SPA catch-all in _redirects: it rejects /* /index.html 200 as an infinite loop, and /* / 200 intercepts assets. --spa therefore omits 404.html, which enables Cloudflare's automatic SPA mode. If you need a real 404, do not use --spa.

Netlify uses the same files plus /* /index.html 200 when --spa is used.

Vercel

Upload dist-static/ and let Vercel read vercel.json (redirects, optional rewrite, cache headers). Set the project output directory to dist-static if you deploy from a Git repository.

Locale redirects use statusCode: 301|302; Vercel's permanent boolean maps to 308/307, not 301/302. The /(.*) rewrite only applies when there is no file at the requested path, so bundles and assets are served normally.

nginx

Copy dist-static/ to the server and include nginx.conf (or merge it into your site config). It maps 404 to /404.html and sets no-store on bundles and env files.

GitHub Pages

Root-only. Two supported shapes:

Publish dist-static/ to the gh-pages branch (or /docs) and configure the custom domain in Settings → Pages. .nojekyll is written automatically.

GitHub Pages has no server redirects and no custom headers. Locale redirects become HTML meta refresh pages; there is no CSP/HSTS control. If the app depends on /api/*, GitHub Pages is not enough: use a separate backend or a host with functions.

--spa on GitHub writes the shell as 404.html, so unknown routes render the app but GitHub still returns 404. A 200 fallback is not possible on Pages.

S3 + CloudFront

Upload dist-static/ with index.html as the default root document and 404.html as the error document. Locale redirects become HTML redirect pages. --spa writes the shell as 404.html (soft 404, status 404). For a true 200 fallback, use a CloudFront function to rewrite navigation requests to /index.html; CustomErrorResponses alone keeps the 404 status.

--host none

No host rules. The folder is portable: index.html, prerendered routes, 404.html, env files and client redirect pages. Use it for a custom server or a host the exporter does not model.

Validate before upload

--check writes nothing and fails when:

  • a required runtime file is missing (index.html, 404.html, routes.js,

sliceConfig.json, the env pair, bundles/bundle.config.json, Slice/Slice.js),

  • Components/ is present without --keep-components,
  • public/ was not flattened,
  • utils/, src/, api/, node_modules/, .git/, AppConfig.js,

slice-events.generated.js or a generated .d.ts is present,

  • any .map, .map.br, .map.gz, .d.ts, .env*, package.json, lockfile,

node_modules or .git is present,

  • an exported .js contains sourceMappingURL=,
  • host rules are incoherent (_redirects without _headers, invalid

vercel.json, nginx without error_page 404 /404.html, explicit GitHub host without .nojekyll),

  • a literal route has no prerendered page and the export has no SPA fallback.

--check does not enumerate ${param} routes or verify every referenced asset.

Environment variables

slice build writes dist/slice-env.json and dist/slice-env.generated.js. The runtime imports the shim, so there is no production env endpoint. Values are frozen at build time: rebuild after changing .env or SLICE_PUBLIC_*.

Only SLICE_PUBLIC_* keys reach the browser. See [Environment Variables](/Documentation/Configuration/environment-variables).
